# 动态提示词注入机制

## 概述

系统通过三类来源向 LLM prompt 注入上下文：**MD 文件**（启动时加载，重启更新）、**数据库表**（每次实时查询，无需重启）和 **blackboard**（完整 history 中的探索结果）。注入点分布在 `Think → Action → Act → Observe` 的各个阶段。

---

## Blackboard 注入（所有阶段）

`conversation_history` 的第一个元素是 blackboard 条目，保存 `explore_schema` / `explore_functions` / `explore_base_knowledge` / `explore_mcp` 的完整搜索结果。`utils/blackboard.py::blackboard_section()` 会将它渲染成独立段落：

```text
## Blackboard

### DB
note: Database schema gathered by `explore_schema`: `selected_fields` lists relevant tables/columns, with schema details and query guidance. Re-running `explore_schema` overwrites this region.
selected_fields:
...
query_guide_content:
...
schema_detail:
...

### FUNC
note: Function catalog gathered by `explore_functions`: `selected_functions` lists callable function names and `func_docs` contains their documentation. Re-running `explore_functions` overwrites this region.
selected_functions:
...
func_docs:
...

### KNOWLEDGE
note: Business domain knowledge gathered by `explore_base_knowledge`: selected knowledge IDs, a summary, and the full content. Re-running `explore_base_knowledge` overwrites this region.
selected_knowledge_ids:
...
knowledge_content:
...

### MCP
note: External MCP tools gathered by `explore_mcp`: selected tools, tool details, and the catalog; call them with `exe_mcp`. Re-running `explore_mcp` overwrites this region.
selected_tools:
...
tool_detail:
...
catalog:
...

### RECENT_GENERATED_IMAGES
note: Images generated by the most recent code execution. They are attached automatically to the next LLM call.
images:
["xxx.png", "http://127.0.0.1:8008/tmp_imgs/yyy.png", "https://example.com/zzz.png"]

### SELECTED IMAGES
note: Images explicitly kept by `select_images`, each with a path and a reason. They stay attached to every later LLM call until the region is overwritten.
images:
[{"path": "xxx.png", "reason": "一句话选中原因"}, {"path": "https://example.com/chart.png", "reason": "一句话选中原因"}]
```

该段会追加到以下所有阶段：

- Think
- Action
- Observe
- Act explore_schema / explore_functions / explore_base_knowledge / explore_mcp
- Act generate_and_execute
- 文档生成（outline / part / unified / YAML outline / YAML section）

每个区域第一行的 `note:` 会说明该区域由哪个 action 写入、主要字段含义以及覆盖规则，因此即使当前阶段没有 action 描述（如代码生成、文档生成），LLM 也能理解区域语义。`### RECENT_GENERATED_IMAGES` 段（来自 `rencent_generated_images` 区域）让 LLM 知道最近一次执行生成了哪些图片及其文件名/URL，并带有 `note` 说明这些图片会自动附带到下一次 LLM 调用；`### SELECTED IMAGES` 段展示 `select_images` 选中的图片及每张图的一句话选中原因，`note` 说明这些图片会持续附带到后续每次 LLM 调用，直到区域被覆盖。除文本注入外，当模型 `supports_images=true` 且请求 `meta.use_images` 开启时，两处图片会按 `rencent_generated_images` 在前、`selected_images` 在后的顺序作为 `image_url` 内容数组随请求提交，每张图片前附带 `Image filename: ...` 文本标签；本地文件/本机静态 URL 转 base64，外部 URL 原样传递。详见 `docs/conversation_history_structure.md`。

普通历史条目由 `prepare_trimmed_context` 裁剪后经 `history_to_text` 渲染成 `## Context`，其中 **不包含 blackboard**，因此两部分不会重复注入。

## 知识源

### 1. MD 文件（启动时加载，重启更新）

存放在 `agent/tools/base_knowledge/knowledge_docs/`，模块导入时通过 `_read_doc()` 读取一次并缓存：

| 文件 | 缓存变量 |
|------|----------|
| `db_brief.md` | `_DB_BRIEF_MD` |
| `base_knowledge.md` | `_BASE_MD` |
| `doc_guide.md` | `_DOC_MD` |
| `target_knowledge.md` | `_TARGET_MD` |
| `think_guide.md` | `_THINK_KNOWLEDGE_MD` |
| `db_query_guide.md` | `_DB_QUERY_GUIDE_MD` |
| `base_knowledge_brief.md` | `_BASE_KNOWLEDGE_BRIEF_MD` |
| `mcp_brief.md` | `_MCP_BRIEF_MD` |
| `custom_func_brief.md` | `_CUSTOM_FUNC_BRIEF_MD` |

### 2. 数据库表（实时查询，无需重启）

位于 `data_copilot_v10_sys` 数据库，每张表结构相同：

```sql
id    INT AUTO_INCREMENT PRIMARY KEY
key   TEXT NOT NULL
value LONGTEXT
```

| 表 | 查询函数 |
|----|----------|
| `base_knowledge` | `get_base_knowledge_db()` |
| `doc_guide` | `get_doc_guide_db()` |
| `db_query_guide` | `get_db_query_guide_db()` |
| `code_guide` | `get_code_guide_db()` |
| `graph_code_guide` | `get_graph_code_guide_db()` |
| `think_guide` | `get_think_guide_db()` |

另外，`brief_info` 表（结构为 `attr` / `value`）用于存储 `db_brief`、`base_knowledge_brief`、`mcp_brief`、`custom_func_brief` 的 DB 覆盖值，与对应 MD 文件合并后注入。

### 3. 动态注入机制：`_DynamicStr`

`get_base_knowledge.py` 定义了一个代理类，使模块级变量在每次使用时重新计算，而非在导入时固定：

```python
class _DynamicStr:
    def __init__(self, func):       self.func = func
    def __str__(self):              return self.func()
    def __add__(self, other):       return str(self) + other
    def __radd__(self, other):      return other + str(self)
    def strip(self):                return str(self).strip()
    def __format__(self, spec):     return format(str(self), spec)
    def __repr__(self):             return repr(str(self))
```

模块级变量将 MD 内容（启动时缓存）和 DB 内容（实时查询）拼接：

```python
def _get_brief_value(attr, md_fallback):
    # 读取 brief_info 表对应 attr 的 DB 值，与 md_fallback 合并
    ...

DB_BRIEF = _DynamicStr(lambda: ("\nDataBase Brief:\n" + v) if v.strip() else "")
MCP_BRIEF = _DynamicStr(lambda: ("\nMCP Brief:\n" + v) if v.strip() else "")
BASE_KNOWLEDGE_BRIEF = _DynamicStr(lambda: _get_brief_value(...))
CUSTOM_FUNC_BRIEF = _DynamicStr(lambda: _get_brief_value(...))

BASE = _DynamicStr(lambda: "\nbase knowledge for reference:\n" + _BASE_MD
       + "\n" + base_knowledge_to_str(get_base_knowledge_db()))
DOC = _DynamicStr(lambda: ("\ndoc reference(just for reference):\n" + _DOC_MD
       + "\n" + base_knowledge_to_str(get_doc_guide_db())) if (_DOC_MD.strip() or get_doc_guide_db()) else "")

TARGET = _DynamicStr(lambda: "\nTarget:\n" + _TARGET_MD)

DB_QUERY_GUIDE = _DynamicStr(_format_db_query_guide)
# _format_db_query_guide() 内部: 内容均为空时返回 ""，不显示标签

THINK_KNOWLEDGE = _DynamicStr(lambda: ("\nthink knowledge for reference:\n" + _THINK_KNOWLEDGE_MD
       + "\n" + base_knowledge_to_str(get_think_guide_db())) if (_THINK_KNOWLEDGE_MD.strip() or get_think_guide_db()) else "")
```

## 按功能划分的注入分析

### 1. Think 阶段 — 分析计划生成

**文件：** `agent/think.py`

**注入的变量：** `TARGET`, `THINK_KNOWLEDGE`, `BRIEF_INFO`, `Blackboard`

**注入方式：** f-string 直接嵌入

```
{TARGET}                  → MD target_knowledge.md（有内容时注入）
{THINK_KNOWLEDGE}         → MD think_guide.md + DB think_guide 表（全量）
{BRIEF_INFO}              → BRIEF_INFO 聚合
                            ├── DB_BRIEF → MD + brief_info.db_brief
                            ├── Domain Knowledge Brief → MD + brief_info.base_knowledge_brief
├── MCP Brief → MD + brief_info.mcp_brief
├── Function Brief → 代码硬编码
└── Custom Function Brief → MD + brief_info.custom_func_brief
{Blackboard}              → blackboard_section(conversation_history)
```

**功能：** Think 阶段生成 todo list 分析计划。各 Brief 提供基础概览，详细业务知识通过 `explore_base_knowledge` action 按需获取。

---

### 2. Action 阶段 — 动作决策

**文件：** `agent/action.py`

**注入的变量：** `BRIEF_INFO`, `Blackboard`

**注入方式：** f-string 直接嵌入

```
{BRIEF_INFO}              → 聚合：DB_BRIEF + BASE_KNOWLEDGE_BRIEF + MCP_BRIEF + FUNCTION_BRIEF + CUSTOM_FUNC_BRIEF
{Blackboard}              → blackboard_section(conversation_history)
```

此外通过 `get_db_summary_for_agent()` 和 `get_func_summary_for_agent()` 动态获取数据库摘要和函数目录。

**功能：** Action 阶段决定下一步执行哪个动作。

---

### 3. Act — explore_schema 子阶段

**文件：** `agent/act.py` → `_act_explore_schema()`

**注入的变量：** `DB_BRIEF`, `DB_QUERY_GUIDE`, `Blackboard`

**注入方式：** f-string 直接嵌入

```
{DB_BRIEF}                → MD db_brief.md + DB brief_info 表
{DB_QUERY_GUIDE}          → MD db_query_guide.md + DB db_query_guide 表（内容为空时不显示标签）
+ full_schema             → 动态查询的数据库结构
{Blackboard}              → blackboard_section(conversation_history)
```

**功能：** 分析用户问题，筛选出所需的数据库表和字段。

---

### 4. Act — explore_functions 子阶段

**文件：** `agent/act.py` → `_act_explore_functions()`

**注入的变量：** `Blackboard`

**注入方式：** 通过 `search_func_by_keyword()` 或 `get_func_catalog_markdown()` 获取函数目录，并追加 `blackboard_section(conversation_history)`

**功能：** 搜索和筛选可用函数。

---

### 5. Act — explore_base_knowledge 子阶段

**文件：** `agent/act.py` → `_act_explore_base_knowledge()`

**注入的变量：** `BASE_KNOWLEDGE_BRIEF`, `Blackboard`

**注入方式：** f-string 直接嵌入

```
{BASE_KNOWLEDGE_BRIEF}    → MD + brief_info.base_knowledge_brief
+ knowledge_text          → get_base_knowledge_db()  ← 仅 base_knowledge 表
{Blackboard}              → blackboard_section(conversation_history)
```

**功能：** 查询业务知识并筛选出相关的条目。doc_guide、think_guide、code_guide 不再由此阶段注入。

---

### 6. Act — generate_and_execute 子阶段（代码生成与执行）

**文件：** `agent/agent.py` → `get_cot_code_prompt()`

**注入的变量：** `BASE`, `TARGET`, `Blackboard`

**注入方式：** 字符串拼接

```python
cot_prompt = pre_prompt + function_prompt + function_info +
             module_prompt + example_code + remind_prompt +
             database + knowledge + blackboard_section +
             target_section + research_section + question
```

各部分说明：

| 注入内容 | 来源 | 说明 |
|----------|------|------|
| `knowledge` | `BASE` + `code_guide` + `graph_code_guide` | MD base_knowledge.md + DB base_knowledge 表 + DB code_guide 表 + DB graph_code_guide 表 |
| `target_section` | `TARGET` | MD target_knowledge.md（有内容时注入） |
| `database` | `get_db_info_prompt()` | 数据库表结构；若 blackboard 已有 `schema_detail` 则跳过，避免重复 |
| `blackboard_section` | `blackboard_section(conversation_history)` | 完整探索结果（DB / FUNC / KNOWLEDGE / MCP） |
| `function_info` | `FUNCTION_DICT` | 选中函数的完整 docstring |
| `research_guide` | Action 阶段传入 | 自然语言描述需要生成的图表和数据 |

**功能：** 生成 Python 代码，调用选中的函数执行数据查询和图表绘制。

---

### 8. Act — generate_document 子阶段（报告生成）

**文件：** `agent/document_generator.py`

**两个生成路径：**

- **分步生成** (`_event_stream_generate_document`): 先由 LLM 生成大纲，再逐部分生成
- **统一生成** (`_event_stream_generate_document_unified`): 一次完整生成

**两个路径均注入变量：** `BASE`, `DOC`, `TARGET`, `Blackboard`

**注入方式：** f-string 直接嵌入

```
{BASE}                    → MD base_knowledge.md + DB base_knowledge 表
{DOC}                     → MD doc_guide.md + DB doc_guide 表
{TARGET}                  → MD target_knowledge.md（有内容时注入）
{Blackboard}              → blackboard_section(conversation_history)
```

上下文部分先经 `prepare_trimmed_context` 裁剪，再由 `history_to_text` 渲染；blackboard 单独注入。

**功能：** 生成业务摘要文档（MD + DOCX + PDF）。`DOC` 提供文档格式参考，`BASE` 提供数据背景，`TARGET` 提供目标模板。

---

### 9. Observe 阶段 — 结果审查

**文件：** `agent/observe.py`

**注入的变量：** `TARGET`, `Blackboard`

**注入方式：** f-string 直接嵌入

```
{TARGET}                  → MD target_knowledge.md（有内容时注入）
{Blackboard}              → blackboard_section(conversation_history)
```

**功能：** 审查执行结果，判断是否达到目标模板要求，更新 todo list。

---

## LLM 搜索流程

`get_*_db_llm()` 函数将查询结果 + 用户上下文发给 LLM，返回结构化结果：

### 事件流格式

```python
yield {"type": "status", "content": "正在分析知识库..."}
yield {"type": "chunk", "content": "LLM 响应的文本片段..."}
yield {"type": "done", "description": "自然语言描述", "useful_ids": [1, 3, 5]}
```

### 可用函数

| 函数 | 说明 |
|------|------|
| `get_base_knowledge_db_llm(context, key)` | 基于 `base_knowledge` 表 + 数据库结构生成查询方案 |
| `get_db_query_guide_db_llm(context, key)` | 基于 `db_query_guide` 表生成 SQL 查询方案 |
| `get_doc_guide_db_llm(context, key)` | 基于 `doc_guide` 表生成文档分析方案 |
| `get_code_guide_db_llm(context, key)` | 基于 `code_guide` 表生成图表代码方案 |
| `get_graph_code_guide_db(key=None, threshold=0.3)` | 读取 `graph_code_guide` 表全部记录（无 LLM 查询版本） |
| `get_think_guide_db_llm(context, key)` | 基于 `think_guide` 表生成思考分析方案 |
